## Meeting Links — GCal-Only Model (v3, April 2026)
### Problem
1. Jitsi fallback (`generateFallbackMeetingLink`) produced identical links across students (hash collision).
2. `meet.google.com/lookup/` URLs are not real room links — they expire/redirect.
3. Frontend called `gcal-sync create_permanent_room` but edge function was blocked by slot fetch before action check (`slotId` was actually `studentId` → 404).
4. `studentId` was not destructured from request body; `req.clone().json()` after consumed body silently failed.
5. Global `calendar_settings.default_meeting_link` leaked as shared fallback even with per-student model active.

### Edooqoo Solution
- **No Jitsi, no lookup, no deterministic hashes.** Auto-generated = only real Google Meet via GCal API.
- Teacher must have active Google Calendar connection for auto-create to work.
- If no GCal → only manual custom link, no fake "default."
- `calendar_student_settings` stores: `generated_meeting_link` (auto), `meeting_link_mode` ('default'|'custom'), `default_meeting_link` (canonical effective link for backward compat).
- Student-facing flows: `slot.meeting_link` > `student_settings.default_meeting_link` > (no global fallback when per-student active).

### Technical Mechanics
- `supabase/functions/gcal-sync/index.ts`: **Critical fix (v3)**: `studentId` added to top-level destructuring. `create_permanent_room` action handled BEFORE slot fetch (early return). Removed broken `req.clone().json()`. Action flow: parse body → get token → if `create_permanent_room` handle and return → else fetch slot → handle `delete`/`cancel`/`upsert`.
- `create_permanent_room` accepts `teacherId + studentId` (no `slotId` needed), checks for existing `generated_meeting_link`, creates ghost event → extracts `hangoutLink` → deletes event → saves to `calendar_student_settings`.
- `src/pages/StudentPage.tsx` `MeetingLinkField`: reads `meeting_link_mode` from DB (no URL heuristics). Default mode triggers edge function if no generated link exists.
- `src/hooks/useStudents.tsx`: on new student + auto-create ON + GCal connected → calls edge function (no local link generation).
- `src/pages/CalendarSettingsPage.tsx`: batch generation calls edge function per student; toggle disabled when no GCal.
- `supabase/functions/get-student-hub-data/index.ts`: returns `studentMeetingLink || null` (no global fallback).
- `src/utils/meetingLinkUtils.ts`: only `isLegacyAutoGeneratedLink()` for backward compat detection.

## Calendar Stability (400 Errors / Freeze)
### Problem
"Zombie" slots (status=booked, student_id=NULL) caused 400 errors during `needs_review` auto-update. Fire-and-forget `.then(() => {})` masked errors, causing infinite re-render loops.

### Edooqoo Solution
1. Added `student_id` guard: `needs_review` auto-update only targets slots where `s.student_id` is truthy.
2. Added error handler: `.then(() => {}, (err) => console.error(...))` instead of fire-and-forget.
3. SQL migration cleaned existing zombie slots: `UPDATE calendar_slots SET status='available' WHERE status='booked' AND student_id IS NULL`.

### Technical Mechanics
- `src/hooks/useCalendarSlots.tsx` lines 103-122: Filter + error handling
- Migration: One-time data cleanup

### RAG Keywords

## Reschedule Decision — GCal Sync & Meeting Link in Email (April 2026)

### Problem
1. `calendar-handle-reschedule-decision` confirm/reject had zero GCal sync calls — teacher and student calendars not updated after reschedule decision.
2. Reschedule confirmation email missing `meetingLink` — no Join Meeting button.
3. `scrollToToday()` in `StudentBookingsSection` fired every 5s due to polling re-triggering the effect.
4. Reschedule UI had no loading feedback — students could click multiple slots during processing.

### Edooqoo Solution
- Confirm: teacher GCal upsert old slot (now available/rescheduled) + upsert new (confirmed). Student GCal delete old + upsert new.
- Reject: teacher GCal cancel new slot. Student GCal delete new pending event.
- Email: fetch `meeting_link` from slot or `calendar_student_settings.default_meeting_link`, pass as `meetingLink` to template.
- Scroll: `hasScrolledRef` ensures `scrollToToday()` runs only once after initial load.
- UI: `rescheduling` state blocks slot clicks and shows `Loader2` spinner during processing.

### Technical Mechanics
- `supabase/functions/calendar-handle-reschedule-decision/index.ts`: After confirm → `gcal-sync upsert` old+new (teacher) + `student-gcal-sync delete` old + `upsert` new. After reject → `gcal-sync cancel` new + `student-gcal-sync delete` new. Before email → fetch meetingLink from slot/student_settings.
- `supabase/functions/get-student-bookings/index.ts`: Auto-reschedule `sendEmail('reschedule_confirmation')` now includes `meetingLink` fetched from slot or student settings.
- `src/components/calendar/StudentBookingsSection.tsx`: `hasScrolledRef = useRef(false)` — scroll executes only when `!hasScrolledRef.current`.
- `src/pages/StudentHubLessons.tsx`: `rescheduling` state set true at start of `handleReschedule`, false after completion. `handleSlotClick` returns early if `rescheduling`. Banner shows spinner during processing.

### RAG Keywords
reschedule gcal sync, confirm reject calendar, meeting link email, scrollToToday fix, reschedule loading, hasScrolledRef, rescheduling state, calendar-handle-reschedule-decision gcal
