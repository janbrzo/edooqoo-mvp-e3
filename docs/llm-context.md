## Meeting Links — GCal-Only Model (v2, April 2026)
### Problem
1. Jitsi fallback (`generateFallbackMeetingLink`) produced identical links across students (hash collision).
2. `meet.google.com/lookup/` URLs are not real room links — they expire/redirect.
3. Frontend never called `gcal-sync create_permanent_room` for per-student default links.
4. Global `calendar_settings.default_meeting_link` leaked as shared fallback even with per-student model active.

### Edooqoo Solution
- **No Jitsi, no lookup, no deterministic hashes.** Auto-generated = only real Google Meet via GCal API.
- Teacher must have active Google Calendar connection for auto-create to work.
- If no GCal → only manual custom link, no fake "default."
- `calendar_student_settings` stores: `generated_meeting_link` (auto), `meeting_link_mode` ('default'|'custom'), `default_meeting_link` (canonical effective link for backward compat).
- Student-facing flows: `slot.meeting_link` > `student_settings.default_meeting_link` > (no global fallback when per-student active).

### Technical Mechanics
- `supabase/functions/gcal-sync/index.ts`: `create_permanent_room` accepts `teacherId + studentId`, checks for existing `generated_meeting_link`, creates ghost event → extracts `hangoutLink` → deletes event → saves to `calendar_student_settings`.
- `src/pages/StudentPage.tsx` `MeetingLinkField`: reads `meeting_link_mode` from DB (no URL heuristics). Default mode triggers edge function if no generated link exists.
- `src/hooks/useStudents.tsx`: on new student + auto-create ON + GCal connected → calls edge function (no local link generation).
- `src/pages/CalendarSettingsPage.tsx`: batch generation calls edge function per student; toggle disabled when no GCal.
- `supabase/functions/get-student-hub-data/index.ts`: returns `studentMeetingLink || null` (no global fallback).
- `src/utils/meetingLinkUtils.ts`: only `isLegacyAutoGeneratedLink()` for backward compat detection.

## Confirm/Reject Inline Comments
### Problem
Sub-dialog for Confirm/Reject didn't open properly (portal conflict with DraggableDialog). Teacher couldn't add comments.

### Edooqoo Solution
Removed sub-dialogs entirely. Added inline checkbox "Add comment" + AutoResizeTextarea directly in the footer of `SlotDetailModal`. Confirm/Reject buttons trigger `handleConfirm`/`handleReject` immediately. Comment from `inlineComment` state is included in email and slot log.

### Technical Mechanics
- `src/components/calendar/SlotDetailModal.tsx`: States `showInlineComment`, `inlineComment` replace old `showConfirmDialog`/`showRejectDialog`/`confirmComment`/`rejectComment`
- Comment passed as `confirmationComment` or `rejectionReason` to `send-calendar-notification-email`

### RAG Keywords

## Calendar Stability (400 Errors / Freeze)
### Problem
"Zombie" slots (status=booked, student_id=NULL) caused 400 errors during `needs_review` auto-update. Fire-and-forget `.then(() => {})` masked errors, causing infinite re-render loops.

### Edooqoo Solution
1. Added `student_id` guard: `needs_review` auto-update only targets slots where `s.student_id` is truthy.
2. Added error handler: `.then(() => {}, (err) => console.error(...))` instead of fire-and-forget.
3. SQL migration cleaned existing zombie slots: `UPDATE calendar_slots SET status='available' WHERE status='booked' AND student_id IS NULL`.

### Technical Mechanics
- `src/hooks/useCalendarSlots.tsx` lines 103-122: Filter + error handling
- Migration: One-time data cleanup

### RAG Keywords
calendar freeze, 400 error, zombie slot, needs review, batch update, calendar stability

## Student Hub Lesson Sorting & Auto-Scroll
### Problem
Lesson cards showed upcoming ascending then past descending (correct logic), but page didn't auto-position to "Today" on load.

### Edooqoo Solution
Added `useEffect` that triggers `scrollToToday()` after bookings load, scrolling only the list container (not the whole page). 150ms delay ensures DOM is ready.

### Technical Mechanics
- `src/components/calendar/StudentBookingsSection.tsx`: `useEffect` on `allBookings.length > 0 && !loading`
- `scrollToToday()` uses `listRef.current.scrollTo()` — container-only scroll

### RAG Keywords
lesson list, student hub, today scroll, auto scroll, lesson sorting, booking list
